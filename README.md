# Ловец заказов

Телеграм-бот, который слушает **все группы и каналы твоих аккаунтов** и присылает
только то, что похоже на лид для IT-фрилансера. Аккаунтов можно подключить
сколько угодно.

Ловит два вида лидов:

1. **Заказ на разработку** — ищут исполнителя под задачу, есть ТЗ, бюджет или
   вакансия.
2. **Ищут готовый софт** — «ищу бота для рассылки», «нужен ловец чеков»,
   «где взять инвайтер», «куплю парсер чатов». Сюда же: рассылка в ЛС, отметки
   в историях, поиск чатов, мониторинг, автоответчик, накрутка, юзерботы.
   Отсеиваются продавцы такого софта («продам», прайс, ссылка на свой бот) и
   вопросы «как написать самому» — нужны именно те, кто ищет.

Вход в аккаунт — прямо через бота: `api_id`, `api_hash`, телефон, код, пароль 2FA.
Сессии сохраняются, после рестарта заново логиниться не надо.

## Как отбираются сообщения

```
сообщение из чата
   ↓  предфильтр (без LLM): пауза, ЧС, длина, дубликаты
   ↓  буфер: 100 сообщений ИЛИ 5 минут — что раньше
   ↓  этап 1: вся пачка одним промптом → отсеиваем явно не то (recall)
   ↓  этап 2: каждое выжившее сообщение проверяется отдельно (precision)
   ↓  порог уверенности + повторная проверка ЧС
уведомление
```

Два этапа нужны, чтобы не гонять дорогую проверку по всему потоку: первый работает
пачками по 25 сообщений в одном запросе, второй — только по единицам, зато вдумчиво.

Порог длины (`MIN_TEXT_LEN`) короткие лиды не режет: «ищу бота для рассылки» —
это 21 символ, но для таких сообщений есть исключение. Оно срабатывает, только
когда рядом стоят и запрос («ищу», «куплю», «где взять»), и предмет («бот»,
«инвайт», «чек»), — «привет всем» и «бот тупит опять» мимо не проходят.

**Чаты с моделью.** Каждый этап ведёт свой непрерывный чат, а не заводит новый
диалог на каждый запрос. Раз в `CHAT_TTL_HOURS` (по умолчанию 6) чат меняется на
свежий — контекст не тянется бесконечно, но и тысяч диалогов не появляется.
В следующий запрос переносится `CHAT_HISTORY_TURNS` прошлых обменов (по умолчанию
один), реплики в истории обрезаются до 400 символов: на 1-м этапе вопрос — это
пачка из 25 сообщений, тащить её целиком в каждый следующий запрос слишком дорого.
Поставь `CHAT_HISTORY_TURNS=0`, если контекст не нужен вовсе — чат останется
одним и тем же, просто без переноса истории. Текущие чаты видно в `/status`.

**Антидубль.** Одно объявление обычно висит в десятке чатов. Дубли режутся ещё
_до_ LLM: точные — по хешу нормализованного текста (ссылки, цифры и пунктуация
из сравнения выброшены), переписанные — по simhash с расстоянием Хэмминга.

Замеры на реальном объявлении: тот же текст — 0, изменён бюджет и срок — 3,
переставлены предложения — 5, добавлена строка с контактами — 9, слегка
перефразировано — 10, **другое объявление — 28**. Отсюда порог по умолчанию
`DEDUP_HAMMING=12`. На коротких сообщениях simhash шумит (одно лишнее слово даёт
16+), поэтому короче 15 слов сравниваются только по точному совпадению.
Память — `DEDUP_TTL_DAYS` дней.

## Установка

```bash
git clone https://github.com/potapenkofil-rgb/orders_catcher
cd orders_catcher
pip install -r requirements.txt
cp .env.example .env
```

В `.env` обязательно заполнить `BOT_TOKEN` — токен у
[@BotFather](https://t.me/BotFather).

Дальше нужно, чем проверять сообщения — одно из двух (можно оба):

- **Аккаунты нейросети.** `/addllm` прямо в боте: email и пароль от
  DeepSeek или Qwen. Ключ не нужен, платить не надо.
- **Ключ.** `LLM_API_KEY` в `.env` — любой OpenAI-совместимый эндпоинт,
  по умолчанию `https://api.aitunnel.ru/v1`.

Запуск:

```bash
python run.py
```

Дальше в боте: `/start` → `/login`. Каждый следующий `/login` добавляет ещё один
аккаунт, а не заменяет прошлый.

`api_id` и `api_hash` берутся на [my.telegram.org](https://my.telegram.org) →
API development tools.

> **Код подтверждения присылай с разделителями:** `1-2-3-4-5` или `1 2 3 4 5`.
> Если отправить пятизначное число как есть, Телеграм увидит код в переписке и
> сразу его аннулирует. Бот сам вырежет всё лишнее и удалит сообщения с секретами.

## Несколько телеграм-аккаунтов

`/login` можно повторять сколько угодно — каждый вызов подключает новый аккаунт.
`/accounts` показывает все: кто на связи, кто выключен, кто отвалился и почему.
Кнопками аккаунт можно временно выключить или отключить совсем (с выходом из
сессии). Повторный вход тем же аккаунтом не создаёт дубль — запись обновляется.

Если аккаунты состоят в одних и тех же чатах, одно и то же сообщение придёт от
каждого. Такие повторы режутся по id сообщения ещё до всякой проверки — уведомление
будет одно. В `/chats` источники сгруппированы по аккаунтам, пометкой `↺` отмечены
чаты, которые видит не один аккаунт.

В уведомлении есть строка `📱 Аккаунт` — через какой аккаунт поймано, чтобы сразу
понимать, с какого отвечать.

Аккаунты стартуют при запуске бота. Не поднялся (сессия протухла, аккаунт
заблокировали) — остальные работают дальше, а причина видна в `/accounts`.

## Аккаунты нейросети

Вместо платного ключа проверку можно гонять через обычные аккаунты чат-нейросетей:
бот логинится по email и паролю и работает через веб-API аккаунта.

```
/addllm   → выбрать DeepSeek или Qwen → email → пароль
```

Бот проверяет вход сразу: логинится и задаёт модели контрольный вопрос. Не вышло —
скажет, почему. Сообщение с паролем удаляется из переписки. `/llm` показывает
все аккаунты нейросети и их состояние, каждый можно выключить или удалить кнопкой.

Аккаунтов может быть сколько угодно. Запрос уходит на тот, что меньше работал;
если аккаунт упал или уткнулся в лимит — он уходит в паузу
(`ACCOUNT_COOLDOWN_MINUTES`, при лимите минимум 30 минут), а запрос
автоматически повторяется на следующем. Когда аккаунты кончились, а ключ в `.env`
есть — запрос уйдёт по ключу. Управляется это через `LLM_BACKEND`
(`auto` / `key` / `accounts`).

**Чаты не плодятся.** В таком API чат — настоящий диалог внутри аккаунта, он виден
в списке чатов. Поэтому на этап заводится один чат, который живёт до смены
(`CHAT_TTL_HOURS`, по умолчанию 6 часов), и в нём же продолжаются все запросы.
Системный промпт уходит только первым сообщением — дальше модель помнит его сама.
Если аккаунт временно выпал и вернулся, продолжается его прежний чат, а не новый:
внутри сессии хранится карта «аккаунт → чат». После перезапуска бота чаты тоже
подхватываются из базы. Итого за сутки — единицы диалогов, а не тысячи.

Запросы внутри одного чата идут строго по очереди: параллельная отправка в один
диалог сломала бы цепочку сообщений на сервере. При нескольких аккаунтах этапы
работают параллельно, при одном — последовательно. В пятиминутное окно батча
это укладывается с запасом.

Библиотеки клиентов лежат в `orderbot/vendor/` (см. `vendor/README.md`) —
пришпиленные копии из проектов `betterDeepseek` и `betterQwen`, импортируются
лениво. Их зависимости (`requests`, `numpy`, `py_mini_racer`) вынесены в
`requirements-accounts.txt`, но подключены строкой `-r` в основной
`requirements.txt` — иначе хостинг-панели, которые ставят только его, роняли бы
`/addllm` с «No module named 'requests'». Не нужны аккаунты — закомментируй эту
строку, минус ~25 МБ памяти и ~100 МБ диска.

> Пароли лежат в локальной базе (`data/orderbot.db`) как есть — иначе боту нечем
> перелогиниться, когда протухнет токен. База в `.gitignore`, но это обычный файл
> на диске: держи его там, где не жалко, и не заводи туда основную почту.

## Команды

| Команда | Что делает |
|---|---|
| `/login` | подключить телеграм-аккаунт (4 шага), можно повторять |
| `/accounts` | телеграм-аккаунты: включить, выключить, отключить |
| `/addllm` | добавить аккаунт нейросети (email + пароль) |
| `/llm` | аккаунты нейросети: включить, выключить, удалить |
| `/logout` | то же, что `/accounts` — отключение кнопкой |
| `/status` | что происходит сейчас: аккаунты, буфер, пачки, ЧС, чаты |
| `/chats` | отслеживаемые группы и каналы по аккаунтам |
| `/pause`, `/resume` | приостановить/продолжить приём |
| `/stats` | статистика за сегодня и за всё время |
| `/bl` | чёрные списки с кнопками «убрать» |
| `/unban_user id`, `/unban_chat id` | убрать из ЧС вручную |
| `/threshold 0.7` | минимальная уверенность для уведомления |
| `/profile текст` | чем ты занимаешься — влияет на отбор |
| `/test текст` | прогнать произвольный текст через оба этапа |

## Уведомление

```
💼 Найден заказ · 87%
🏷 разовый заказ
🛠 телеграм-бот на Python
💰 10 000 ₽

💬 Чат: Фриланс IT
👤 Автор: Иван (@ivan)
📱 Аккаунт: Рабочий (@work_acc)
🆔 123456789

> текст сообщения целиком

[🔗 Открыть сообщение]
[🚫 Автора в ЧС] [🚫 Чат в ЧС]
[🗑 Скрыть]
```

У лида на готовый софт заголовок другой — `🤖 Ищут готовый софт`, а в строке
`🛠` перечислены нужные функции (рассылка, инвайтинг, ловец чеков и т.д.),
чтобы такие заявки было видно с первого взгляда.

Кнопки ЧС работают мгновенно: автор или чат больше не проверяются вообще —
их сообщения отсекаются ещё на предфильтре, до всяких запросов к LLM.

## Настройки

Всё через `.env` (см. `.env.example`). Основное:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MODEL_STAGE1` | `gemini-3.6-flash` | дешёвая модель для пачек |
| `MODEL_STAGE2` | `claude-haiku-4.5` | точная модель для единичных проверок |
| `BATCH_SIZE` / `BATCH_TIMEOUT` | `100` / `300` | условия сборки пачки |
| `STAGE1_CHUNK` | `25` | сообщений в одном промпте 1-го этапа |
| `STAGE2_CONCURRENCY` | `4` | параллельных проверок 2-го этапа |
| `MIN_CONFIDENCE` | `0.65` | порог уверенности |
| `LLM_BACKEND` | `auto` | `auto` / `key` / `accounts` — чем проверять |
| `ACCOUNT_COOLDOWN_MINUTES` | `20` | пауза для аккаунта после ошибки |
| `CHAT_TTL_HOURS` | `6` | как часто менять чат с моделью |
| `CHAT_HISTORY_TURNS` | `1` | сколько прошлых обменов переносить в запрос |
| `DEDUP_TTL_DAYS` / `DEDUP_HAMMING` | `7` / `12` | глубина и чувствительность антидубля |
| `OWNER_ID` | — | если пусто, владельцем станет первый написавший `/start` |

Порог, профиль и пауза меняются на лету командами и переживают рестарт —
они хранятся в SQLite (`data/orderbot.db`), туда же кладутся ЧС, сессия и статистика.

## Расходы на LLM

Основной поток съедает 1-й этап: пачка из 100 сообщений — это 4 запроса
по 25 штук. 2-й этап дороже за штуку, но работает по единицам.
Если поток большой, подними `MIN_TEXT_LEN`, ужесточь `PROFILE` или поставь
на 1-й этап модель подешевле.

## Тесты

```bash
python tests/smoke_test.py
```

174 проверки без единого сетевого запроса: батч-буфер (флаш по размеру и по
таймауту, приём во время обработки), антидубль, разбор ответов LLM (фенсы,
болтовня вокруг, кривые типы, отказ модели), фильтрация в пайплайне, ЧС,
короткие софт-лиды, чаты с моделью (ротация, перенос истории, параллельные
запросы, восстановление после рестарта), выбор бэкенда и откат на ключ,
пул аккаунтов нейросети (ротация, кулдаун, продолжение чата вернувшимся
аккаунтом), мультиаккаунт в телеграме (переезд со старой схемы, повторный вход,
выключение и удаление, один пост от двух аккаунтов), вёрстка уведомления,
сохранение состояния между рестартами.

Живой логин в DeepSeek/Qwen тестами не покрыт — там нужна настоящая учётка
и сеть. Вся логика вокруг него (выбор аккаунта, кулдауны, чаты) гоняется
на подменённом адаптере.

## Что важно знать

- Юзербот — это **твой личный аккаунт**, а не бот-аккаунт. Массовые рассылки
  и агрессивная автоматизация с него могут привести к блокировке — здесь
  аккаунт только читает входящие апдейты и ничего никуда не пишет.
- Личные переписки не читаются вообще: обрабатываются только группы и каналы.
- Файл `.env`, база `data/` и сессия не попадают в git (см. `.gitignore`).

## Структура

```
run.py                точка входа
orderbot/
  app.py              сборка и запуск
  config.py           конфиг из .env
  bot.py              команды, логин, кнопки
  userbot.py          Telethon: аккаунты, вход, прослушка чатов
  pipeline.py         предфильтр → батч → этап 1 → этап 2 → отправка
  buffer.py           батч-буфер (100 сообщений / 5 минут)
  classifier.py       промпты и вызовы LLM
  dedup.py            антидубль (хеш + simhash)
  notifier.py         вёрстка уведомления и кнопки
  llm/                чаты, бэкенды, пул аккаунтов
  vendor/             пришпиленные клиенты DeepSeek и Qwen
  state.py            ЧС, пауза, порог — в памяти и в базе
  db.py               SQLite
  models.py           датаклассы
  utils.py            мелочи
```
